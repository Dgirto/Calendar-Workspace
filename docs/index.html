Google Calendar (Google Workspace — cuenta de servicio)

{{ULTIMA_ACTUALIZACION}}

¿Qué es y para qué sirve?

Este conector permite que el agente de Ruvic gestione los calendarios de los usuarios de tu dominio Google Workspace mediante una cuenta de servicio con delegación de dominio: una sola credencial, autorizada por el superadministrador, puede actuar en nombre de cualquier usuario del dominio sin que cada uno autorice individualmente y sin tokens que expiren. Puedes pedirle al agente cosas como:

  • “Agenda una reunión en el calendario de soporte@empresa.com mañana a las 3 pm.”
  • “¿Qué tiene agendado facturación esta semana?”
  • “Cancela la reunión de seguimiento del viernes del calendario de ventas.”

Operaciones soportadas:

Operación Qué hace
calendar.create_event Crea un evento (con horario o de día completo), con descripción, ubicación e invitados opcionales
calendar.list_events Lista los eventos de un rango de fechas, con búsqueda por texto
calendar.cancel_event Cancela un evento y notifica a los invitados
Solo Google Workspace La delegación de dominio no existe en las cuentas de Google personales. Para una cuenta personal usa el conector Google Calendar (OAuth2).

Prerrequisitos

  • Un dominio de Google Workspace activo (cualquier plan).
  • Acceso de superadministrador al Admin Console del dominio (solo durante la configuración, para autorizar la delegación).
  • Acceso a Google Cloud Console para crear la cuenta de servicio (o reutilizar la de los otros conectores Workspace: Gmail, Sheets, Drive, Docs).

Configuración en el fabricante

Si ya configuraste otro conector Workspace (Gmail, Sheets, Drive, Docs) con cuenta de servicio, reutilízala: solo necesitas los pasos 2 y 4 (habilitar la API y agregar el scope de Calendar a la entrada de delegación existente).

  1. Crea la cuenta de servicio.

    En Google Cloud Console → “IAM y administración → Cuentas de servicio” → Crear. No necesita roles del proyecto. Luego “Claves → Agregar clave → JSON” y descarga el archivo de credenciales.

  2. Habilita la Google Calendar API.

    En “APIs y servicios → Biblioteca” del mismo proyecto, busca Google Calendar API y pulsa Habilitar.

  3. Copia el Client ID numérico.

    En los detalles de la cuenta de servicio (o en el campo client_id del JSON descargado). Es un número largo, distinto del correo de la cuenta.

  4. Autoriza la delegación de dominio (superadministrador).

    En admin.google.com → “Seguridad → Control de acceso y datos → Controles de API → Delegación en todo el dominio” → Agregar nueva: pega el Client ID y el scope https://www.googleapis.com/auth/calendar.events. Si la entrada ya existe (otros conectores Workspace), edítala y agrega este scope separado por coma.

Permisos requeridos

Principio de mínimo privilegio: la delegación se autoriza con un único scope.

Permiso Para qué sirve
calendar.events Crear, listar y cancelar eventos de los calendarios accesibles por el usuario impersonado. No permite cambiar la configuración de los calendarios, ni compartirlos, ni acceder a correo o archivos del dominio.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Google Calendar (Google Workspace — cuenta de servicio) y pulsa Configurar:

Campo del formulario Valor
JSON de la cuenta de servicio Contenido completo del archivo JSON descargado en el paso 1 (se guarda cifrado como secreto)
Usuario de prueba Un correo del dominio (ej. facturacion@tuempresa.com); solo se usa para el botón “Probar conexión”
Timeout de solicitud Opcional; 30 segundos por defecto

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa: delegación de dominio válida para tu-usuario@tudominio.com”. La tarjeta cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Crea un evento de prueba mañana a las 10 am en el calendario de [usuario del dominio] y dime qué tiene agendado esa mañana.” El evento debe aparecer en el Google Calendar de ese usuario. Después pídele que lo cancele.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“No se pudo autenticar como '…' (unauthorized_client)” La delegación no está autorizada: falta el Client ID en el Admin Console, el scope no coincide exactamente con calendar.events, o el usuario no pertenece al dominio. Revisa el paso 4 de la sección 3 (los cambios tardan hasta 10 minutos en aplicar).
“La Google Calendar API no está habilitada en el proyecto…” Falta el paso 2 de la sección 3. El propio mensaje incluye el enlace de activación; habilítala y espera 1-2 minutos.
“El JSON de la cuenta de servicio no tiene el formato esperado…” Se pegó el JSON incompleto o el de otro tipo de credencial (cliente OAuth). Descarga de nuevo la clave de la cuenta de servicio y pega el contenido completo.
“El evento o calendario solicitado no existe…” El event_id es incorrecto, el evento ya fue eliminado, o el usuario impersonado no tiene acceso a ese calendario. Lista los eventos de nuevo para obtener el id vigente.
Funciona con un usuario pero falla con otro El segundo usuario no pertenece al dominio autorizado (la delegación cubre un dominio, no cuentas externas ni alias de otros dominios secundarios no autorizados).

Preguntas frecuentes y notas de seguridad

¿La cuenta de servicio puede leer el correo o los archivos del dominio?

No con este conector: la delegación se autoriza solo con el scope calendar.events. El superadministrador ve (y controla) la lista exacta de scopes en el Admin Console.

¿Dónde queda guardado el JSON de la cuenta de servicio?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarlo; solo indica “definida”.

¿Cómo se revoca el acceso?

El superadministrador elimina la entrada de delegación en el Admin Console (efecto inmediato en todo el dominio), o elimina/rota la clave de la cuenta de servicio en Google Cloud Console.

¿Expiran las credenciales?

No. Las claves de cuenta de servicio no expiran solas — por eso conviene rotarlas periódicamente (crear clave nueva, actualizar el formulario, eliminar la anterior) según tu política de seguridad.

Buenas prácticas Usa una cuenta de servicio dedicada a Ruvic; autoriza solo los scopes que el catálogo necesita; rota la clave JSON periódicamente; y elimina la entrada de delegación si dejas de usar los conectores Workspace.
